# E-0.1.2 更新内容

**主题：下载链路全量审计修复（1 P0 + 7 P1 + 10 P2 + 遗留项全量清扫）**　versionCode 102

2026-11-21 发布。对下载视频/图片链路（入口解析 / 直连选源 / yt-dlp 引擎 / 任务账本四段）做全量审计后同批修复，高危发现均经人工二次复核；审计标记「择机处理」的遗留项本版一并清完。

## 数据安全（P0）

- **画质升级器坏文件顶替根治**：视频替换前增加完整性校验（时长可读 + 时长不显著短于原文件 + Content-Length 收满校验）——服务端提前断流/中间盒劫持返回截断体时，坏产物不再顶替并删除原好文件。图片路径原有的 1.05x 对比保持不变，HLS 升级路径同步加时长校验。

## 取消语义（P1 三连）

- **取消一次秒取消砖死根治**：直连引擎任务（xinvox_/bgimg_）此前从不注销取消标记——下载中心取消一次后，同推文重试会秒命中残留标记自取消，直到杀进程。现任务创建即登记、终态即注销，新下载起点统一回收整推文残留标记。
- **取消不再被记成失败**：新增 `Cancelled` 结果语义——取消不烧 attemptCount、不设自动重试时间、不记引擎熔断/亲和。旧实现取消记 FAILED 并 30 秒自动复活，与「取消→秒取消」循环叠加烧光全部重试额度。
- **取消「准备下载」占位真实生效**：取消升级为推文级——总线内该推文全部活跃任务逐个取消+杀进程，另写推文级会话信号兜底「引擎链启动期任务尚未创建」的取消窗口。

## 内容错配（P1 三连）

- **yt-dlp 输出模板加推文 id**：同作者文案开头相同的两条推文不再标题碰撞（旧实现第二条不下载，把旧推文文件改名挂到新推文名下）；「已存在」产物行同步校验身份。
- **多视频推文逐文件入库**：裸推文链接对多视频推文是播放列表——旧实现全部下载只入库第一个，其余滞留孤儿目录且推文标成功；现解析全部产物按视频序号逐个落位，任一产物无效整单失败。画质升级器对多视频推文跳过（防拿 video#1 内容顶替 video#N）。
- **混合推文补图序号对齐**：补图沿用全媒体列表序号（旧实现用过滤后序号，图 B 被旧图 A 文件冒名判完成，图 A 重复两份、图 B 永久缺失）；补图按原序号回写任务清单（键校验防错记）。
- **图前视频后推文高画质恢复**：yt-dlp 的 /video/N 按推文全媒体列表取位（含图片），旧实现用「仅视频计数」导致该类推文探测必败、静默回退直连。

## 其他 P1

- **订阅页 Bluesky/Instagram 作品下载按钮**：暂无对应下载通道，点按不再烧重试额度（报错即失败不记账）。*（完整多平台下载通道后续版本评估）*

## 可靠性（P2）

- **下载失败不再双烧额度**：持久队列 Worker 此前对失败任务立即原样重跑整条引擎链——现只承接 PENDING（进程被杀续跑场景不受影响），失败交还自动重试按退避单烧。
- **「配 Cookie 无条件 HLS 升级」救活**：判定提到画质比较闸门之前——HLS-only 推文（恰是目标场景）此前被闸门永久跳过。
- **磁盘满治理**：分段下载入口按 2× 文件大小水位预检（合并阶段峰值），合并阶段磁盘满清段文件释放空间并给人话提示；`可用空间==0` 漏判修复。
- **第三方兜底（默认关）**：m3u8 播放列表不再被当 mp4 落成假成品；部分成功不再置 DOWNLOADED（缺的媒体交重试补齐）。
- **收件箱进度会话分界**：改锚「最近占位任务时间」——占位被取消后历史会话任务不再泄入分母。
- **选源降质守卫**：基准分辨率与码率全缺失时不再盲目换源（任何低质候选不再恒判「更优」）。
- **download_tasks 死层删除**（DB v17）：该持久层从未通电（无写入调用方、恢复入口零调用），删除实体与整层代码并 DROP 存量表；进程被杀恢复由 WorkManager 队列承担（行为不变）。

## 体验（P3）

- 下载中心失败/取消任务不再残留半截进度条；批量下载胶囊不再混入批外（订阅线）进度；单卡下载防连点。
- 收件箱粘贴路径 t.co 展开加 8 秒总超时（与分享路径同口径，最坏 15 秒空转修复）。
- yt-dlp 自救热修不再被「全引擎跳过」的断网请求白白消耗（每进程仅一次的机会留给真失败）。
- yt-dlp 引擎成功纳入引擎健康记账；sidecar 改 tmp+rename 原子写（进程被杀不落残缺 JSON）；元数据补拉不再对已删除推文每轮空耗请求。

## 遗留项清扫（同批完成）

- **回收站快照补来源线**（EdqiuDatabase v12）：deleted_link_history 加 origin 列——订阅作品删除→恢复后不再错落用户收件箱（双线隔离修复）；备份/恢复模型同步补 origin 字段（旧备份 JSON 向后兼容）。
- **收件箱幽灵条目根治**：扫描导入路径改用严格版文件名解析（只认下载器规约名），文件名里裸 11-25 位数字串（epoch 毫秒时间戳等）不再被赋伪推文 id；yt-dlp 中间态产物（`{标题}.f137.mp4`）在下载窗口期不再被收件箱/媒体库扫描误收。
- **取消/失败语义收尾**：会话内有失败任务时不亮 99% 哨兵（消除引擎空窗「99→低位」锯齿）；抓取入库异常不再谎报「都已在收件箱里」。
- **下载中状态修复**：单格式回退下载（GIF 无独立音轨）进度不再恒卡 ≤50%——按 yt-dlp「Downloading N format(s)」info 行动态定分母；ETA ≥1h 不再显示错（库只认 mm:ss，自行解析 h:mm:ss）。
- **网络与解析**：t.co 短链展开跟随应用内代理（此前恒直连，对主要受众形同虚设）；同一条推文的元数据抓取单飞化（不再双倍请求白耗限流）。
- **URL 与格式**：图片 name=orig 替换改精确参数匹配（username=/nickname= 不再被误截）；heic/avif 进图片扩展名白名单；第三方兜底视频扩展名按 URL 实推。
- **账目与卫生**：引擎亲和记忆写入时顺带清理过期项；下载互斥锁清理竞态修复（改常驻不清理，避免临界区互斥失效）；批量粘贴超 8192 字符明确提示「仅解析前 N 字符」；扫描导入插入后复查回收站（删除竞态窗口收窄）；DELETED 终态不再被扫描静默翻转为 DOWNLOADED；yt-dlp 产物规约化后清理空作者子目录。

## 引擎独立更新（轻云控）

- **yt-dlp 引擎可独立于 App 发版更新**：设置 → 更新与工具新增「立即更新」入口与版本显示。随包库 0.18.1 内置 2025.11 构建，此后 yt-dlp 官方每天发版——X 改接口时不再需要等 App 发版（反编译随包库实证：冷启动仅在二进制缺失时从 APK 释放，云端更新的版本重启保留；落点/版本账本与库内更新器同键）。
- **双通道自动回退**：① 代理直连 GitHub API/资产（用户常开代理，显式 Proxy 对象）；② 失败回退 gh-proxy.com 镜像直连——与 App 更新检查同构。下载产物校验（≥1MB + zip 容器头）+ 同目录原子落位，进程被杀不落半截引擎。
- **自救热修同步修复**：三层全挂触发的每进程一次热修从「库内更新器（JVM 代理属性注入，Android 上不可靠）」切换到同一自研更新器，墙内真正可用。
- 注：SHA256 清单校验属完全云控（C 档）范畴，本档以 HTTPS + 双通道 + 完整性下限兜底。
