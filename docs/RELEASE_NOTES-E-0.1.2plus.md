# E-0.1.2plus 更新内容

**主题：公告云控触达双修（真机首日实测抓出）**　versionCode 102（补丁 tag，覆盖安装兼容）

2026-11-21 发布。公告云控首发（`x_api_manifest.json` announcements，收件箱顶部公告胶囊）当日真机验证时发现公告无法到达设备，定位出两个独立缺陷并同批修复。

## 为什么会收不到公告（双因定位）

### 因一：7 天清单 TTL 锁死公告（`XApiClient.maybeQuietUpgrade`）

真机 12:21 装机 E-0.1.2，首轮订阅轮询立刻拉过一次清单（当时公告字段还为空）；14:26 公告推送上线——`manifestAt` 已记到 12:21，7 天 TTL 把下次拉取锁死到 11-28。7 天是 queryId 保鲜的节奏，公告等不起。

**修复**：公告感知 TTL——与调用方显式 TTL 取小：

- announcements 缓存为空（从未收到过公告）→ **1h 加速**，新公告最迟约 1 小时内（下一轮订阅轮询，25 分钟周期）触达
- 已有公告缓存 → **24h** 天级保鲜，后续公告最迟一天内送达
- 不影响调用方显式短 TTL（FXTwitter 全主机失败 1h 重试路径不变）

### 因二：横幅组合时只读一次 prefs（`ListScreen.AnnouncementBanner`）

清单拉取在启动 90 秒后由订阅轮询后台落盘，而横幅的 `remember {}` 无键、只在组合时求值——当次会话横幅不现，重启才见。真机复现：14:46 logcat「manifest 已热更新」落盘成功，屏幕无横幅；14:47 重启后横幅出现。

**修复**：新增 `XApiClient.onAnnouncementsChanged` prefs 落盘监听（前台拉取即时刷新）+ ON_RESUME 重读（后台轮询落盘后回到前台即时可见）。反注册闭包持有 prefs/listener 强引用，防 SharedPreferences 监听器弱引用回收的经典坑。

## 真机验证记录

- 装机后首轮轮询拉取成功：logcat `XApiClient: manifest 已热更新`
- 重启后收件箱顶部公告胶囊完整渲染（文案 / 查看详情 › / 知道了 / info 语义点）
- 修复版同签名覆盖安装无回归（数据无损）
- prefs 监听路径经编译+评审验证，自然触发待下次清单拉取（≤24h）

## 升级说明

- versionCode 仍 102 / versionName 仍 E-0.1.2：补丁 tag（`E0.1.2plus`，继 `E0.1.2fix` 约定）重出安装包，**旧版本直接覆盖安装兼容**
- 应用内更新版本号数字段相等不弹提示，需手动下载安装
- 受众边界（设计使然）：E-0.1.1 及更早版本无公告解析代码，收不到公告；公告送达以代理开启为前提（清单拉取仅在代理开启时静默触发）
- 发布后运营：发新公告/改公告只需改仓库 `x_api_manifest.json` 的 announcements 数组推 main，**无需发版**；装了本版的用户最迟约 1 小时（首条）/ 24 小时（后续）自动收到
