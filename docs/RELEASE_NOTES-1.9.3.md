# v1.9.3 更新内容

**主题：作者订阅 X 检测通道重建 + 订阅改选择性下载 + 预下载退役 + 弹窗体系升级**　versionCode 52

## 作者订阅 · X 检测通道重建（核心修复）

- **旧通道废弃**：v1.9.2 的 X 订阅检测依赖 yt-dlp 提取用户主页时间线，而 yt-dlp 从不支持该页面（`Unsupported URL`）——检测通道自上线起即不可用，且失败被静默吞掉、界面永远显示「暂无新作品」
- **重建为 X GraphQL 直连**：guest token 主通道（免登录、零配置）→ 登录 Cookie 兜底；检测到疑似降级数据时自动升级 Cookie 通道，无 Cookie 时如实标注
- **新鲜度门闩**：游客时间线最新推文超过 30 天视为被 X 降级（实测个别大 V 账号如此），自动走 Cookie 通道复核
- **queryId 远程静默轮换**：X 定期轮换接口 ID，App 检测到陈旧签名后拉取仓库 `x_api_manifest.json` 热更新并重试；代理开启时每 7 天静默保鲜——接口变更不再需要发版
- **失败九类分类透出**：未走代理 / 代理超时 / 代理不可达 / X 限流 / Cookie 失效 / 接口轮换失败 / 账号不可访问 / 响应异常 / 网络错误——每条带可操作指引，订阅行常驻 ⚠ 显示，不再静默吞成「暂无新作品」

## 订阅改为选择性下载

- 检测到新作品**只收录进收件箱与「订阅消息」，不再自动下载**——你在订阅消息或收件箱里点按后才下载（与手动下载同语义、同保护）
- **订阅起始日期自定义**：给订阅设一个日期（如 10-17），轮询只检测该日期**之后**发布的新帖，更早的历史帖不再涌进收件箱
- **订阅消息区重做三段式**：① 顶部新作品数量卡（待下载计数）② 检测状态卡（逐作者上次检测时间 / 失败原因 / 最近事件——失败出现与失败消失都有记录）③ 帖子列表（与收件箱同款卡片，待处理/失败的帖子可直接点按下载）
- 轮询每轮每作者最多收录 8 条；消息文案如实标注「已加入收件箱，点按下载」

## 预下载功能退役

- 预下载（保存链接攒批自动下载）整体移除，含设置页开关与「待处理 ≥ 5」提示弹窗——它与手动下载高度重叠，且是本次「订阅拖垮下载」事故的第三方路径
- 下载完成后的网盘自动联动保留
- 收件箱右上角「下载」批量下载全部待处理的能力不变（就是原来的入口，只是名字更诚实了）

## 下载与弹窗体系升级

- **引擎熔断按发起方隔离**：后台/系统路径的下载失败不再计入全局熔断器——订阅检测批量触发下载失败曾把熔断器打满，导致手动下载被误伤报「引擎熔断中」；现在只有用户手动下载的失败才会触发熔断保护
- **操作结果升级中央弹窗**：批量下载汇总（成功/失败/跳过条数）、单条下载失败（含三级引擎链具体原因）、无效链接——必须点掉确认，不再一闪而过；保存成功、已复制等瞬时状态仍走底部玻璃胶囊
- **胶囊提醒抬升**：移到底部 Tab 栏上方 12dp，不再遮挡 Tab 栏
- **弹窗宽度与动画**：弹窗加宽至 86% 屏宽（上限 560dp，修复大屏上的迷你弹窗）；退场动画改并行单段 180ms（修复消失时的停顿感）；单按钮弹窗按钮居中；失败文案不再把「单条近期失败」误报为「引擎熔断」

## 兼容性

- 主库 v12 → v15（订阅失败原因 / 订阅消息表 / 订阅起始日期）；订阅库 v10 → v11（作品来源标记）——全部自动迁移，数据无损
- `x_api_manifest.json` 随仓库分发：远程轮换源，改此文件即可热更新所有客户端的检测接口
